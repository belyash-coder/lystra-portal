# Деплой на Coolify

Код лежит в подпапке `cinema/` в том же репозитории, что и `lystra-portal`, но разворачивается
как отдельный сервис — со своим доменом, своей базой (новая БД в существующем Postgres) и своим
Telegram-ботом.

## 1. TMDB API-ключ

1. Зайдите на https://www.themoviedb.org/ и зарегистрируйтесь (нужно подтвердить email).
2. Войдите → иконка профиля справа сверху → **Settings**.
3. В левом меню → **API**.
4. Нажмите **Create** (или "Request an API Key").
5. Выберите тип **Developer**, примите условия использования.
6. Заполните форму заявки:
   - Application Name: например, `КиноБиблиотека`
   - Application URL: можно указать будущий домен приложения или ссылку на репозиторий
   - Application Summary: коротко — личный некоммерческий каталог фильмов для себя/семьи
7. Отправьте — ключ обычно выдаётся сразу, без модерации.
8. Скопируйте **API Key (v3 auth)** — именно это значение, НЕ "API Read Access Token (v4 auth)"
   (код использует v3-ключ). Это и есть `TMDB_API_KEY`.

## 2. OMDb и Кинопоиск — для «честного» рандомайзера (необязательно)

Рейтинг TMDB часто завышен у свежих/хайповых релизов. Если в рандомайзере задать минимальный
рейтинг, приложение дополнительно проверяет его по IMDb и Кинопоиску и выбирает случайный фильм
только среди тех, что подтвердились хотя бы одним из этих источников с достаточным числом
голосов. Без этих ключей всё остальное (включая сам рандомайзер без фильтра по рейтингу) работает
как обычно — фильтр по рейтингу просто не будет ничего находить.

**OMDb** (рейтинг IMDb):
1. https://www.omdbapi.com/apikey.aspx → выберите Free (1000 запросов/день) → укажите email.
2. Ключ придёт на почту (может занять пару минут), подтвердите по ссылке из письма.
3. Это `OMDB_API_KEY`.

**Кинопоиск** (через неофициальный kinopoisk.dev):
1. https://kinopoisk.dev/ → зарегистрируйтесь, возьмите бесплатный тестовый ключ на странице
   аккаунта.
2. Это `KINOPOISK_API_KEY`.
3. Важно: это неофициальный сторонний сервис (не от Яндекса), у него есть лимиты и он может
   измениться/сломаться без предупреждения — это не так надёжно, как TMDB или OMDb.

## 3. Telegram-бот — кнопка меню с Mini App

У вас уже есть токен бота. Осталось привязать к нему Mini App:

1. Откройте Telegram, найдите **@BotFather**, отправьте `/mybots`, выберите своего бота.
2. **Bot Settings → Menu Button → Configure menu button**.
3. BotFather попросит URL — отправьте `https://` + домен, который вы дадите сервису в Coolify
   (шаг 5), например `https://cinema.вашдомен.ру`.
   - Домен можно задать заранее, даже если сервис ещё не задеплоен — Telegram проверяет
     доступность в момент открытия приложения пользователем, а не в момент настройки.
4. Затем отправьте текст кнопки, например `Открыть библиотеку`.
5. Готово: в чате с ботом внизу появится кнопка меню, открывающая приложение как Mini App.

Альтернатива для более "нативного" вида — команда `/newapp` (полноценная регистрация Mini App
с иконкой и описанием, отдельная ссылка `t.me/ваш_бот/app`). Для личного использования обычной
Menu Button вполне достаточно.

## 4. Новая БД в существующем Postgres

1. В Coolify откройте тот же проект, где развёрнут `lystra-portal` и его Postgres-ресурс.
2. Откройте ресурс базы данных (Postgres), которым пользуется lystra.
3. На вкладке ресурса найдите **Terminal** (или "Execute Command") — shell внутри контейнера БД.
4. Подключитесь к psql и создайте новую базу:
   ```bash
   psql -U <POSTGRES_USER> -d <существующая_база_lystra>
   ```
   а внутри psql:
   ```sql
   CREATE DATABASE cinema;
   \q
   ```
   (`POSTGRES_USER` и имя текущей базы lystra — на вкладке **Configuration/Environment
   Variables** этого же ресурса в Coolify).
5. Проще всего собрать строку подключения так: откройте у **lystra-portal** его переменную
   `DATABASE_URL` (в настройках сервиса lystra в Coolify) и скопируйте её — там уже правильные
   хост, порт, пользователь и пароль. Замените в конце только имя базы на `cinema`:
   ```
   postgresql://<user>:<password>@<тот-же-хост>:5432/cinema
   ```
   Это и есть `DATABASE_URL` для нового сервиса.

## 5. Сервис в Coolify

1. **New Resource → Application**.
2. Источник — тот же репозиторий, что у lystra-portal (`belyash-coder/lystra-portal`), тем же
   способом подключения, что уже настроен.
3. Ветка: `claude/web-cinema-app-coolify-5dww2u` для проверки (после мёржа PR — переключите на
   `main`).
4. **Base Directory / Root Directory** (в General-настройках приложения): `/cinema` — обязательно,
   иначе Coolify будет собирать корень репозитория, где лежит lystra, а не новое приложение.
5. **Build Pack**: Nixpacks — сам определит Next.js/npm, отдельный Dockerfile не нужен.
6. **Port**: `3000`.
7. Вкладка **Environment Variables** — добавьте:
   - `DATABASE_URL` — из шага 4
   - `AUTH_SECRET` — случайная строка (сгенерировать: `openssl rand -base64 32`)
   - `TELEGRAM_BOT_TOKEN` — токен вашего бота
   - `TMDB_API_KEY` — ключ из шага 1
   - `OMDB_API_KEY`, `KINOPOISK_API_KEY` — ключи из шага 2 (необязательно, можно добавить позже)

   Важно: `DATABASE_URL` должен быть доступен **на этапе сборки**, потому что `npm run build`
   сам делает `prisma db push` — создаёт таблицы прямо при сборке. Если у переменной в Coolify
   есть галочка "Available at Buildtime" / "Build Variable" — включите её для `DATABASE_URL`.
   У lystra-portal сборка устроена так же и уже работает в этом окружении, так что сеть между
   сборкой и БД точно проброшена.
8. Вкладка **Domains** — привяжите домен/поддомен, тот же, что указали в BotFather (шаг 3).
   Coolify сам выпустит HTTPS-сертификат через Let's Encrypt.
9. Нажмите **Deploy** и смотрите логи сборки.

Таблицы в новой базе создадутся автоматически при первом деплое, отдельные миграции запускать
не нужно.

## 6. Проверка

Откройте бота в Telegram, нажмите кнопку меню — должна открыться библиотека фильмов (пустая при
первом запуске). Добавьте первый фильм через поиск TMDB и проверьте, что рандомайзер его находит.

Если вместо приложения видите ошибку "Откройте приложение через Telegram-бота" — значит страница
открыта не изнутри Telegram (например, напрямую в браузере) или `TELEGRAM_BOT_TOKEN` не совпадает
с ботом, через который открывали.
